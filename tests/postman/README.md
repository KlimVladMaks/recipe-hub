# Postman-коллекция для проверки развёрнутого RecipeHub (ЛР4)

`recipe-hub.postman_collection.json` — самодостаточный сценарий для проверки
сервиса, развёрнутого на удалённом VPS (nginx → api-gateway → user/recipe).
Покрывает как минимум один комплексный сценарий работы приложения и **не
оставляет мусора в БД**: все созданные данные удаляются в конце, а факт
удаления проверяется повторным запросом.

## Что проверяется

1. **Health** — все три микросервиса через шлюз:
   `GET /api-gateway-health`, `/user-service-health`, `/recipe-service-health`
   (статус 200, тело — объект, `status` содержит `OK`, есть `timestamp` и `uptime`).
2. **Справочники (bootstrap-админ)** — вход `admin`/`admin123`, создание типа
   блюда и ингредиента, поиск по ним.
3. **Основной сценарий** — регистрация/вход автора → создание двух рецептов
   (со справочниками, медиа и сложностью) → шаги → поиск и фильтры
   (`difficulty`, `dishTypeIds`, `ingredientIds`) → обновление рецепта →
   рейтинг → комментарий и лайки → избранное → регистрация подписчика →
   подписка → персональная лента.
4. **Очистка** — удаление комментария, рецептов (каскад), справочников и обоих
   пользователей. После очистки проверяется, что сущности отдают `404`, а вход
   удалённых пользователей — `401`.

Все ответы валидируются `pm.test`: статус-коды, обязательные поля и формат
конверта пагинации `{ items, total, page, limit }`.

## Запуск через Newman (терминал)

Из каталога `tests`:

```bash
npm install          # подтянет newman (devDependency)
npm run test:postman
```

Или напрямую без установки зависимости:

```bash
npx newman run tests/postman/recipe-hub.postman_collection.json
```

По умолчанию коллекция обращается к `http://139.100.225.216/api`. Адрес можно
переопределить переменной коллекции или окружения:

```bash
# через переменную окружения Newman
npx newman run tests/postman/recipe-hub.postman_collection.json \
  --env-var baseUrl=http://<IP_СЕРВЕРА>/api
```

```bash
# или через файл окружения Postman (environment.json):
# { "values": [{ "key": "baseUrl", "value": "http://<IP>/api", "enabled": true }] }
npx newman run tests/postman/recipe-hub.postman_collection.json -e environment.json
```

> `baseUrl` уже включает суффикс `/api`, поэтому в запросах путь указывается
> без него (например, `{{baseUrl}}/auth/register`).

## Запуск в Postman UI

1. Import → выбери `recipe-hub.postman_collection.json`.
2. При необходимости поправь переменную коллекции `baseUrl`.
3. Открой коллекцию → **Run** (Collection Runner) → выбери все папки и запусти.

Сценарий автоматический: имена пользователей, названия справочников и текст
комментария генерируются в prerequest-скриптах, поэтому повторные прогоны не
конфликтуют с уже существующими данными.

## Учётные данные

- Bootstrap-админ: `admin` / `admin123` (создаётся user-service из
  `ADMIN_USERNAME`/`ADMIN_PASSWORD`). Если на сервере они изменены, поменяй
  переменные `adminUsername` / `adminPassword`. Админ намеренно **не удаляется** —
  это служебная seed-запись.
- Обычные пользователи создаются и удаляются внутри сценария.

## Замечания

- Порядок папок и запросов важен: очистка идёт последней и зависит от id,
  сохранённых в переменные на предыдущих шагах.
- Если какой-то assert упал, Newman продолжает выполнение, поэтому очистка
  всё равно отработает (кроме случая, когда не удалось создать сущность и
  соответствующая переменная осталась пустой).
